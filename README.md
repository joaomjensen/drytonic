# drytonic

**Deterministic mechanical gates against AI-generated code slop — executable rules instead of verbose `AGENTS.md` prose.**

`drytonic` gives coding agents a small, auditable set of hard stops: a pre-edit guard for governance and protected tests, and a post-edit AST linter for the six failure modes that quietly turn "working code" into unmaintainable code. It supports Python, TypeScript and JavaScript.

## Why drytonic?

Long instruction files are a weak interface for machines. The empirical picture is uncomfortable:

- **ETH Zurich (`arXiv:2602.11988`)**: AI-generated `AGENTS.md` files raised inference cost by **+20%** while *reducing* task success by **-3%**. More prose made agents slower and worse.
- **GitClear**: AI-assisted code showed **+47% swallowed exceptions** and **+81% code clones** — exactly the failures a mechanical gate can catch.
- **Brown / Utah**: dense, immediate compiler/linter feedback accelerates LLM self-correction. Agents improve when the toolchain answers crisply, not when a manifest explains ideals.
- **METR**: developers were **+19% slower** on real tasks while *perceiving* themselves as faster under AI. Speed illusions do not survive measurement.

So: stop negotiating with prose. Put the rule in the toolchain and let the agent fail fast, fix, and leave an auditable reason when an exception is deliberate.

## How the gates work

```
                     +-------------------------------+
 agent edit -------->| PreToolUse                    |
 .py/.ts/.tsx/       | tonic guard <path>            |
 .js/.jsx            | .opencode/**  .tonic/**       |
                     | rules/**      test files      |
                     +---------------+---------------+
                                     |
                    blocked (exit 2) +--> allowed
                                     v
                     +-------------------------------+
                     | file is written to disk       |
                     +---------------+---------------+
                                     v
                     +-------------------------------+
                     | PostToolUse                   |
                     | tonic check <path>            |
                     | ast-grep: TN001 ... TN006     |
                     +---------------+---------------+
                                     |
                    violated (exit 2)+--> pass
                                     v
                     +-------------------------------+
                     | allow_agent_ignore            |
                     | # tonic-ignore TN003: <why>   |
                     | // tonic-ignore TN005: <why>  |
                     | (reason >= 5 chars, in diff)  |
                     +-------------------------------+
```

Both hooks are generated by `tonic init`. OpenCode tracks an edit with `callID` from `tool.execute.before` (guard) through `tool.execute.after` (check); Claude Code uses `PreToolUse` / `PostToolUse` shell hooks. There is no "please be careful" step.

## Quickstart

```bash
uvx drytonic init        # one-shot, no install required
# or
pip install drytonic
tonic init               # writes all three gate files into the current repo
```

`tonic init` creates:

| File | Purpose |
| --- | --- |
| `.tonic/config.json` | enabled rules, protected test globs, `allow_agent_ignore` |
| `.opencode/plugins/drytonic.js` | OpenCode `guard` + `check` hooks, with `callID` correlation |
| `.claude/settings.json` | Claude Code `PreToolUse` / `PostToolUse` hooks |

### Commands

```bash
tonic init                                   # install the mechanical gates
tonic check .                                # lint all supported files recursively
tonic check src/app.py src/api.ts            # lint specific files
tonic guard src/app.ts                       # pre-edit gate: governance / protected tests
tonic dispute tests/test_api.py \
  --reason "contract changed" \
  --proposal "assert the new DTO shape"      # open a human-reviewed dispute
```

`tonic check` walks `.py`, `.ts`, `.tsx`, `.js` and `.jsx`, selects the `python`, `typescript`, `tsx` or `javascript` `ast-grep` grammar automatically, and skips `.venv`, `__pycache__`, `node_modules`, `dist` and `.next`.

## The rules

`allow_agent_ignore: true` (the default) lets an agent suppress a rule **only** with an inline, reviewed reason. Set it to `false` to force human review for every exception.

| ID | Gate | Python | TypeScript / JavaScript |
| --- | --- | --- | --- |
| **TN001** | Empty handler | bare/empty `except` or `pass`/`...` body | `catch (err) {}` or `catch {}` |
| **TN002** | Log-and-swallow | `print` / `logger.error` in `except` without `raise` or `return` | `console.log/error/warn` in `catch` without `throw` or `return` |
| **TN003** | Silent fallback return | `return None/False/[]/{}/''/""` | `return null/undefined/false/[]/{}/''/""` |
| **TN004** | Contextless rethrow | `raise NewError(...)` without `from err` | `throw new Error(...)` without `{ cause: err }` |
| **TN005** | Unsafe catch type | broad `except Exception` / `BaseException` | `catch (err: any)` |
| **TN006** | Loop silent continue | `continue` inside `except` | `continue` inside `catch` |

Protected tests default to `**/test_*.py`, `**/*_test.py` and the `*.test.*` / `*.spec.*` variants for TS/JS. Editing them requires `tonic dispute`; editing `.opencode/**`, `.tonic/**` or `rules/**` is always blocked.

## A real gate in action

```
$ edit src/profiles.py   # agent adds a "quick fix"

$ tonic check src/profiles.py
[TN003] Silent Fallback Return em src/profiles.py:14:9
├─ Trecho bloqueado:
│  except ConnectionError:
│      return None
├─ Motivo:
│  Retornar valor vazio (None, [], {}, False, '') dentro de except mascara erro de infraestrutura como dado válido.
└─ Como corrigir:
│  1. Propague a exceção ou retorne um tipo discriminado de falha.
│  2. Se o fallback vazio for contrato explícito, justifique: `# tonic-ignore TN003: <motivo>`

[TN005] Broad Exception Swallow em src/profiles.py:22:9
├─ Trecho bloqueado:
│  except Exception:
│      return fallback_profile()
├─ Motivo:
│  Capturar Exception ou BaseException sem relançar engole erros inesperados de programação.
└─ Como corrigir:
│  1. Restrinja o except às exceções esperadas da operação (ex: `OSError`, `KeyError`).

2 violação(ões) em 1 arquivo(s) verificado(s).

$ # The agent cannot silently ship it. It must either fix the code
$ # or leave a reason that shows up in the diff and in review:

  except ConnectionError:  # tonic-ignore TN003: profile is optional; null is the documented API contract
      return None

  except Exception:  # tonic-ignore TN005: boundary handler for third-party SDK; incident logged and re-raised
      logger.exception("SDK failure")
      raise

$ tonic check src/profiles.py
OK: 1 arquivo(s) passou(ram) nas regras ativas.
```

In TypeScript the same exception looks like `// tonic-ignore TN005: SDK error is untyped at this boundary`. The comment is data, not decoration: it has a rule ID and a reason of at least five characters, and `allow_agent_ignore: false` rejects it entirely.
